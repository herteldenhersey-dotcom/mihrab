## 1. Executive Summary

Phase 4 turns the MİHRAB onboarding pipeline into the first genuinely usable
consumer-quality Home screen.  After onboarding completes and a valid
`AppLocation` is persisted, the application now:

- Routes directly to the **real Home screen** (no restart required).
- Calculates today's **and** tomorrow's prayer times using the existing
  `AdhanPrayerTimeProvider` / `GetPrayerTimesUseCase` pipeline.
- Resolves and applies the **selected location's IANA timezone** (not the
  device timezone) for date arithmetic and countdown.
- Displays a **live HH:mm:ss countdown** that is clock-anchored (no drift),
  lifecycle-aware, and midnight-safe.
- Shows a **Gregorian date** formatted with `intl` for TR / EN / AR locales.
- Shows a **Hijri date** (approximated via the existing Kuwaiti algorithm).
- Lists all **six daily times** (Fajr · Sunrise · Dhuhr · Asr · Maghrib ·
  Isha) with Sunrise visually distinguished from the five obligatory prayers.
- Handles **missing location**, **offline** (cached data), and **failure**
  states gracefully.
- Reacts to **location changes without a restart** via `LocationChangeNotifier`.
- Passes **155 tests (20 skipped, 0 failed)** — all Phase 3 tests intact.

## 6. Home Data Flow

```
AppLocation (Hive)
  │
  ▼
HomeCubit.load()
  │
  ├─► CoordinateTimezoneRepository.resolveFromCountryCode()
  │      → IANA ID (e.g. "Europe/Istanbul")
  │      → cached in Hive for offline use
  │
  ├─► TZDateTime.now(tz.getLocation(tzId))
  │      → locationNow  (DateTime in selected-location timezone)
  │
  ├─► GetPrayerTimesUseCase(today)   → DailyPrayerTimes today
  ├─► GetPrayerTimesUseCase(tomorrow) → DailyPrayerTimes tomorrow
  │
  ├─► PrayerTimeUtils.getNextObligatoryPrayer(today, locationNow,
  │       tomorrow: tomorrow)        → NextPrayer {type, time, isTomorrow}
  │
  ├─► PrayerTimeUtils.getCountdown(nextPrayer.time, locationNow)
  │      → Duration countdown
  │
  ├─► HomeCubit._formatGregorian(locationNow, lang)
  │      → "15 Mart 2024" / "15 March 2024" / "١٥ مارس ٢٠٢٤"
  │
  ├─► HomeCubit._formatHijri(locationNow)
  │      → "4 Ramazan 1445" (approximated)
  │
  └─► emit(HomeLoaded(...))
```

Every second the countdown timer fires `_onTick()`, which:

1. Calls `clock.now()` — re-reads the wall clock.
2. Computes `locationNow` from IANA timezone.
3. Computes remaining duration from `nextPrayer.time − locationNow`.
4. If the prayer has passed → calls `_loadForLocation()` to reload.
5. Emits `HomeLoaded` with updated `locationNow` and `countdown`.

No heavy I/O, no astronomical recalculation per second.

## 7. Timezone Strategy

1. **Source priority:**  
   a. `AppLocation.timezoneId` (persisted from onboarding via `flutter_timezone` device lookup or manual selection) — used directly when available.  
   b. `CoordinateTimezoneRepository.resolveFromCountryCode(country, longitude)` — country-code table with longitude disambiguation for multi-zone countries (e.g. Russia, US).  
   c. `CoordinateTimezoneRepository.resolveTimezone(lat, lng)` — longitude-band fallback (±15° steps).  
   d. `getCachedTimezone()` — last successfully resolved value from Hive.

2. **Storage:** IANA ID stored in `AppSettings` Hive box.

3. **No device-timezone assumption** on the Home screen.

4. **Failure:** If all paths fail, `HomeFailure('homeTimezoneUnavailable')` is emitted.

## 8. DST Handling

The `timezone` package (pub.dev `^0.9.4`) ships the full IANA `tzdata`
database compiled into Dart.  `TZDateTime.now(location)` and
`TZDateTime.from(dt, location)` automatically apply the correct DST offset for
the given moment.  No manual UTC-offset arithmetic is used.

---

## 9. Selected-Location Date Strategy

```dart
final location  = tz.getLocation(tzId);   // loaded from IANA database
final locationNow = TZDateTime.now(location); // wall-clock, location-aware
final today    = DateTime(locationNow.year, locationNow.month, locationNow.day);
final tomorrow = today.add(const Duration(days: 1));
```

"Today" is always the calendar day in the **selected location** — not the
device's local timezone.  All date arithmetic (Gregorian, Hijri, countdown)
uses `locationNow`.

## 11. Today / Tomorrow Strategy

Both days are loaded eagerly on every full load and on `onResume` when the date
has changed.  Tomorrow is passed to `getNextObligatoryPrayer()` so that the
after-Isha → tomorrow-Fajr edge case is always covered.  "Tomorrow" is computed
as `today + 1 day` in the selected-location timezone (correctly handles month
boundaries and DST gaps).

---

## 12. Next-Prayer Semantics

`PrayerTimeUtils.getNextObligatoryPrayer()` iterates `DailyPrayerTimes.ordered`
and skips any entry where `PrayerType.isObligatory == false`.  Currently only
`PrayerType.sunrise` has `isObligatory = false`.

Behaviour matrix:

| Clock window | Next Prayer shown |
|---|---|
| Before Fajr | Fajr (today) |
| Fajr → Dhuhr | Dhuhr (**not** Sunrise) |
| Dhuhr → Asr | Asr |
| Asr → Maghrib | Maghrib |
| Maghrib → Isha | Isha |
| After Isha | Fajr (tomorrow, actually calculated) |

## 13. Sunrise Handling

Sunrise is shown in the prayer-times list (`PrayerTimeListTile`) with a visual
distinction (italic label, secondary-color icon) to communicate that it is an
important daily time but **not** one of the five obligatory prayers.

It is **excluded** from "Next Prayer" candidates via the `isObligatory` flag.  
No UI-level conditional is used; the domain flag governs the exclusion.

ARB key `homeListSunriseNote` renders a localised subtitle ("Nafile vakti"
/ "Non-obligatory" / "وقت تطوع").

## 14. Countdown Implementation

```dart
// Every second:
final locationNow = _toLocationTime(clock.now(), tzId);
final remaining   = nextPrayer.time.difference(locationNow);
if (remaining <= Duration.zero) { _loadForLocation(...); return; }
emit(loaded.copyWith(locationNow: locationNow, countdown: remaining));
```

- Source of truth: `clock.now()` (injected `Clock` abstraction, wall-clock in
  production, `FakeClock` in tests).
- Never decrements a stored value — recomputes from real time on every tick.
- Timer is `Timer.periodic(1 second, _onTick)`.
- Timer cancelled in `HomeCubit.close()` and on every `_loadForLocation()` call
  before a new timer is started.

---

## 15. Lifecycle Handling

`HomeCubit` implements `WidgetsBindingObserver` and registers itself in `load()`.

```
AppLifecycleState.resumed → onResume()
  ├─ Recompute locationNow
  ├─ If date changed → _loadForLocation() (full reload)
  └─ Else → restart countdown timer with current nextPrayer target
```

No per-second heavy operations (no Hive reads, no timezone resolution, no
astronomical calculation on tick).

## 16. Location-Change Reactivity

`LocationChangeNotifier` exposes a `Stream<AppLocation>`.  On `HomeCubit.load()`
the cubit subscribes; when a new location arrives it calls
`_loadForLocation(location, forceTimezoneResolve: true)` which fully reloads
prayer times and timezone for the new location without requiring an app restart.

Callers (e.g. a future Settings screen) call
`LocationChangeNotifier.notify(newLocation)`.

## 17. Gregorian Date Implementation

```dart
await initializeDateFormatting(lang);          // idempotent
final fmt = DateFormat.yMMMMd(lang);           // intl locale-aware
gregorianFormatted = fmt.format(locationNow);  // "15 Mart 2024" / "15 March 2024" / ...
```

`lang` is obtained from the persisted `AppLanguage` setting.  The displayed
date uses `locationNow` (selected-location timezone), not `DateTime.now()`.

## 18. Hijri Implementation and Limitations

The existing `AppDateUtils.toHijri()` (Kuwaiti algorithm) is used.

**Limitations (documented, not hidden):**

- The Kuwaiti algorithm is a mathematical approximation; it may be ±1 day
  compared to crescent-sighting or regional authority calendars.
- Month names in ARB files are transliterated (TR / EN / AR).
- This is **not** an official religious calendar.
- A future phase may add a ±day user adjustment or an online Hijri API.

The UI renders a disclaimer subtitle (`homeHijriApprox`) below the Hijri date.

---

## 19. Offline Behaviour

1. `AppLocation` is persisted in Hive — available without network.
2. IANA timezone ID is cached in Hive after first successful resolution.
3. Prayer times are computed by `adhan` (pure Dart, no network).
4. If timezone resolution fails and a cached value exists, the cached value
   is used without emitting an error.
5. First offline launch after cache is populated: fully functional.
6. First-ever launch offline with no cached timezone: `HomeFailure` emitted.

## 25. Performance Considerations

- Prayer times are calculated **once per load event** (initial load, date
  transition, location change, manual refresh, `onResume` when stale).
- Countdown tick (`_onTick`) performs only: clock read → TZDateTime conversion
  → Duration subtraction → `emit()`.  No Hive I/O, no astronomical calculation,
  no network.
- `initializeDateFormatting()` is called once per `_formatGregorian` invocation
  but is idempotent (no repeated work after first call).
- `TZDateTime.now(location)` is O(1) — just an offset lookup.

## 36. Known Limitations

   future phase.

### 41.4 Timezone Mimarisi Doğrulaması

`CoordinateTimezoneRepository` gözden geçirildi. Mimari **yeniden
tasarlanmadı** — yalnızca gerçek doğruluk riski taşıyan noktalar incelendi.

**Çözümleme önceliği (HomeCubit `_loadForLocation` içinde):**
1. **`AppLocation.timezoneId` (kalıcı, tam IANA)** — mevcutsa doğrudan
   kullanılır. Bu, spesifikasyonun "mümkün olduğunda bilinen/kalıcı tam IANA
   timezone tercih edilsin" gereksinimini karşılar. **Tam kimlik her zaman
   önce gelir.**
2. **`resolveFromCountryCode(country, longitude)`** — ISO-3166-1-alpha-2 ülke
   kodu → IANA tablosu. Tek-zamanlı ülkeler için (~150 ülke) tam eşleşme;
   çok-zamanlı ülkeler için (ABD, Kanada, Rusya, Avustralya, Brezilya,
   Endonezya) **boylam-bandı** ile en uygun zaman dilimi seçilir.
3. **`resolveTimezone(lat,lng)` → `_longitudeFallback(longitude)`** — ülke kodu
   bilinmediğinde (okyanus koordinatları, kod içermeyen jeokodlama) **son
   çare** olarak boylam/15 UTC-offset yaklaşımı.
4. **`getCachedTimezone()`** — SharedPreferences önbelleğinden son bilinen değer.

**Boylam-bandı fallback'inin doğruluk sınırları:**
- **Ne zaman kullanılır:** Yalnızca (a) çok-zamanlı bir ülkede şehir seçimi
  veya (b) ülke kodu hiç çözümlenemediğinde. Kalıcı tam IANA kimliği varsa
  **asla** kullanılmaz.
- **Belirsiz olabilecek bölgeler:** Çok-zamanlı ülkelerin zaman dilimi
  sınırlarına yakın şehirler (örn. ABD'de Indiana/Kentucky bölünmeleri,
  Avustralya'da Broken Hill, Rusya'da bölge sınırları); okyanus/uluslararası
  sular koordinatları; küçük/ihtilaflı bölgeler ve komşu ülke sınırındaki
  yerleşimler. Bu durumlarda komşu bir zaman dilimi seçilebilir (tipik hata:
  ±1 saat).
- **Tam IANA belirlenemediğinde ne olur:** Uygulama **çökmez** — sırasıyla
  ülke-kodu tablosu → boylam yaklaşımı → önbellek → (hepsi başarısızsa) UTC
  varsayılanına düşülür ve namaz vakitleri yine de hesaplanır. Kullanıcıya
  yanlış zaman diliminde vakit gösterme riski, yalnızca yukarıdaki sınır
  durumlarıyla sınırlıdır.

**Sonuç:** Kalıcı tam IANA kimliği önce tercih edildiğinden ve yaygın
şehirlerin tamamı ülke-kodu tablosuyla doğru çözümlendiğinden, mevcut mimari
V1 için yeterlidir. **Düzeltme gerektiren gerçek bir doğruluk hatası
bulunmamıştır.** İleride kullanıcı tarafından manuel zaman dilimi seçimi
(Settings) ve gerçek bir enlem/boylam→IANA poligon veri seti (örn. `tz_world`)
teknik borç olarak kaydedilmiştir (bkz. Bölüm 37).
